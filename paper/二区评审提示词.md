## 1. 研究问题与核心主张

**威胁**：LLM agent 通过 MCP 等工具协议多轮调用外部工具。攻击者把一个秘密（如 24 字节凭证）切成 k 片，嵌在正常任务里分批经工具外传——**每次调用单独看都合法**（同标签、同目的地、同参数域），拼起来才是完整泄露。

**核心构造（必要性）**：构造 τ 对——良性臂与危险臂的**最后一次调用逐字节相同**（同 effect/labels/state），仅历史不同（危险臂此前已写入同一 (entity, field) 的 k−1 片）。则：任何只看"当前调用 + 标量累计"的防御对两臂**必然同判**（两臂的每次调用计数/字节数逐对相同，实测 32/32 与 104/104）。标量配额的可行集只有两个角：(0, U=0)（全拦）或 (risk=1, U=1)（全放）——**不存在 (risk=0, U>0) 的配置**。

**机制（被检验的假设）**：在逐调用层之上加一个**跨调用覆盖闭包**（K_B）：按 (entity_id, field) 记录已外送字节的区间并集，覆盖率 ≥ θ 即拒——区分能力来自"跨调用的实体连续性"这个逐调用层不可见的信号。

**主张边界（预注册措辞）**：主张形式为"可行性前沿 + 机制必要性"，**不主张**"端到端解决 prompt injection"、"G7 良性完成率 100% 是独立卖点"（良性臂深度 < θ 是构造使然）、"优于所有现有系统"。

## 3. 对照方法的代表性说明

对比点共 8 个：**3 个独立维度**（输入侧 Spotlighting＝近两年提示注入防护代表；输出侧 DLP/LLM judge＝工业实际部署形态；CaMeL＝已发表 IFC 系统）+ **5 个自建消融阶梯**（逐组件拆装）。未包含：其他 prompt-injection 防御的实测（如仅输入侧的其他方案）、agentdojo 全量基准（预注册裁剪，见 Limitations）。

## 4. Limitations（预注册分诊后 5 条；底稿 14 条逐条带出处进可复现包）

1. **判定集范围**：单一场景族（S2b 工具外传）；M2（双字段聚合）与 linkage（关联）类出局——占构造总数 17.5%（22/126），其行为已补测刻画（M2 被拦/linkage 平凡同判）但**不在主判定集**；identity 类（j\*=1）结构性排除。
2. **机制边界**：`K_B` 的覆盖判据是**标签盲且内容盲**的结构判据——任何使受保护 (entity, field) 格子覆盖率越过 θ 的调用都被拦，无论良性与否（S5 整字段常量写 3/3 误拦；真实任务小字段一次写即满同款）。
3. **标定与尺度**：`K_A` 绝对配额**尺度依赖**——按 S2b 碎片尺度标定的 40 字节预算，在公开基准 τ²-bench 真实任务（168–869 B）上良性完成 **0/15**；标定曲线已交付（拐点 ≈350 B/通道），`K_B` 的字段 scoping 是开放设计问题。
4. **外部确认的层次**：CaMeL `MEASURED` 仅覆盖**官方策略引擎层**（未跑其解释器与 LLM 流水线——端到端 pilot 三轮 236 次调用无法推进至 sink 判定，五卡点均在该研究原型代码：解释器不支持切片、异常 redaction 死循环等，分层留证）；CXI 仅原文对位；PACE 无公开工件。
5. **评测设置**：LLM 在环单模型（qwen3.8-max）；对照限定"逐调用"粒度；判定集 18 clusters（预注册上限）中 13 实测；编码威胁在该模型未复现（36/36 拒绝 vs 明文 6/6 遵循，同 payload 对照）。

## 5. 诚实的弱点补充（供评判，不辩解）

- 全部实验在**自建 harness + 自建场景**上执行；外部系统只有 CaMeL 一个、且只到策略引擎层；
- 攻击由确定性驱动与 LLM agent 生成，**无自适应攻击者**（攻击者不看防御反馈）；
- 场景多样性受限：单工具面（3 工具）、单数据形状（CSV 片段）；
- 机制的两个组件在真实任务尺度各有已量化的失效模式（L2/L3）；
- 无复杂性/归约类理论结果（定位为机制构造 + 实证）。
